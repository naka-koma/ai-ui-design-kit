# 視覚参考を設計判断へ翻訳する

参考サイト、ギャラリー、Pinterest、スクリーンショットは「この雰囲気にする」ための完成仕様ではない。観察の材料として使い、対象製品の目的・内容・操作に合う判断へ翻訳する。

## 使う場面

ユーザーが参考を渡したとき、既存のvisual languageを探すとき、主要画面の方向を決めるときに使う。参考がない通常の小修正では不要。著作物の画面、コピー、画像、独自イラストやロゴを複製しない。

## 観察

「かっこいい」「かわいい」「高級感がある」で止めず、次を具体的に記す。スクリーンショットだけでは分からない挙動は推測と明記する。

| 観察軸 | 問うこと |
| --- | --- |
| 第一印象 | 静か、硬質、親密、力強い等、どんな印象か。どの要素が最初に見えるか |
| 構成と余白 | 要素は何を中心に並び、どこに密度差や余白があるか |
| 文字組み | 見出し・本文・補助情報のサイズ、太さ、行長、揃え方の差は何か |
| 色と面 | 色数、コントラスト、背景、境界、写真・テクスチャーが担う役割は何か |
| 画像と素材 | 被写体、切り取り、比率、反復が内容の理解にどう効くか |
| 操作と動き | hover、切替、スクロール、遷移が状態理解にどう寄与するか。未確認なら未確認 |
| 製品との関係 | 参考の事業・画面目的・情報量は、対象製品とどこが同じでどこが違うか |

## 翻訳

観察ごとに、採用判断を1つに絞る必要はない。採用・適応・不採用を選び、理由を記録する。

| 結論 | 記録すること |
| --- | --- |
| 採用 | 残す意図、実装する要素、適用画面、検証方法 |
| 適応 | 参考のどの原理を、対象の内容・signature・アクセシビリティに合わせてどう変えるか |
| 不採用 | 見た目は魅力的でも、用途・情報量・操作性・既存方針に合わない理由 |

例: 「大きな見出しがかっこいい」ではなく、「見出しと補足の明確なサイズ差が、最初に製品の価値を読ませている。対象のLPでは同じ優先順位を採用する。ただし英字専用の極端な文字詰めは日本語本文へ持ち込まない」と書く。

## 実装前の確認

- 参考の見た目ではなく、どの意図を取り入れるか説明できる。
- 既存の `docs/design/signature.md` と矛盾しない。変えるなら製品の判断として記録する。
- 実データ、狭い幅、長い文、空・エラー状態で成立する。
- 文字の可読性、キーボード操作、動きの代替を確認する。
- 参考の独自素材・コピー・ロゴを使わない。

プロジェクトに残す場合は `docs/design/references.md` のVisual reference notesへ、URLではなく観察と採用判断を主に記録する。主要画面ならSubject Swapも実施する。
