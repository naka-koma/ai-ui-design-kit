# 避ける判断

| 症状 | 判断の修正 |
| --- | --- |
| 製品名を替えるだけのhero、KPIカード、装飾グラデーション | 主要タスクとsignatureへの寄与を確認する |
| 全画面を広い余白と丸いカードへ正規化 | 既存の密度・構成を支える仕事を調べる |
| 個性を出すための特殊フォームや強制モーション | 標準操作を維持し、必要な場所の表現を見直す |
| 薄い小文字で階層を表現 | 読める状態で配置・余白・ウェイトを使う |
| アクセシビリティ設定を選ぶまで読めない | 既定表示を修正する |
| WCAG合格だけで視覚レビューを終了 | 読みやすさ・階層・主タスクを別に確認する |
| Setup時の無断リデザイン、Syncで設計文書を置換 | 導入・共通更新・Design Auditを分ける |
| 文書に全token値を転記 | 正本のコードへリンクし、意図だけ記録する |

カード、グラデーション、丸み自体を禁止しない。目的・既存方針・使いやすさに根拠があるかで判断する。
