# Product Signature

signatureはロゴやアクセント色だけではない。情報密度、ナビゲーション、面の質感、構成、動き、操作モデル、テーマの振る舞いに表れる。

`docs/design/signature.md` に次を根拠付きで記す。

| 項目 | 内容 |
| --- | --- |
| Must preserve | 製品らしさを担う意図・パターンと適用画面 |
| May adapt | 画面幅・入力方式・用途に応じて変えてよい強度や構成 |
| Must not compromise | 可読性、操作完遂、状態理解など守る品質 |
| Accessibility adaptations | コントラスト・動き・透過等への具体的な対応 |
| Canonical implementation references | 正確な値を保持するtokens・CSS・コンポーネント |

## 問題がある場合の順序

1. 意図を維持した実装修正を試す（透過面なら文字の背後に安定した下地を用意する等）。
2. 強度、コントラスト、時間、透過度、余白を局所調整する。
3. 適用可能なOS・ブラウザー設定を尊重する。
4. 実際にユーザー差がある場合、アプリ側にも持続的な設定を用意する。
5. それでも操作や理解を損なう場合、表現の撤去・根本変更を理由とともに検討する。

任意のアクセシビリティモードを理由に、既定表示の問題を放置しない。逆にWCAGを理由として、暗色、密度、質感などを一律の白いカードUIへ置換しない。

主要画面の変更では [Subject Swap](subject-swap.md) を使い、どの特徴が名前やコピーに依存せず残っているか確認する。
