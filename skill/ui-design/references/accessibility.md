# Accessibility baseline

Webでは [WCAG 2.2](https://www.w3.org/TR/WCAG22/) のレベルA・AAを既定基準とする。以下は実装時の入口であり、適合に必要な全項目を網羅したチェックリストではない。各基準の適用条件と例外は原文を確認する。

- 文字コントラストは通常4.5:1、大きな文字は3:1（1.4.3）。必要なUI境界や状態表示にも非テキストコントラストを確認する（1.4.11）。
- キーボード操作、論理的なフォーカス順、可視フォーカスを確認し、固定要素でフォーカス対象を完全に隠さない（2.1.1、2.4.3、2.4.7、2.4.11）。
- ズームと狭い幅で情報や操作が失われないことを確認する（1.4.4、1.4.10）。二次元表などの例外は基準に沿って判断する。
- ポインターのターゲットは24×24 CSS pxまたは規定の例外を満たす（2.5.8）。用途に応じてさらに押しやすくする。
- ドラッグのみの操作には代替を用意する（2.5.7）。フォームのラベル、エラー、名前・役割・値、状態通知を確認する。

## 操作と表示を検証する

hoverだけで情報を隠さず、focus・active・selected・disabled・loading・empty・error・successを必要に応じて設計する。disabledの理由やエラーからの復帰を理解できるようにする。ダイアログのフォーカス移動と復帰、スクリーンリーダーでの意味も確認する。

## ユーザー設定と品質

動きを減らす設定に対応し、状態理解を損なわない静的表現を用意する。透過・ぼかしが読み取りを妨げる場合は安定した下地を設け、利用環境で対応できるOS・ブラウザー設定やアプリ設定を検討する。これはWCAGの全てのAA必須項目と同義ではなく、追加の使いやすさの方針も含む。

設定が未指定・未対応でも既定表示をアクセシブルにする。signatureは [product-signature](product-signature.md) の順序で適応する。自動検査に加えてキーボード、実際の表示、必要な支援技術で確認し、実行していない検証は明示する。
